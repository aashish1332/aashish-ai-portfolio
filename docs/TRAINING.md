# TRAINING — corpus, tokenizer, model, checkpoints

How to build the data, train the tokenizer, run the smoke test, and what
exactly has and has not been verified. Every command below is runnable from
the repository root.

**P3 status.** The tokenizer, model code, parameter counter, data pipeline
and checkpoint/resume machinery are built and tested. Two of P3's three
gates — *loss decreases* and *resume verified* — require PyTorch, which is
not installed on this machine, so they are recorded as **UNVERIFIED** here
and are executed in P4 on Kaggle. What *is* verified locally is listed at
the end of this file, with the commands that produce it.

---

## 1. The dev fixture vs the real corpus

`data/raw/seed/*.txt` is a **dev fixture**, generated by
`training/scripts/make_seed_corpus.py`:

* every line is written by us (hand-written templates and slot fills), so
  there is no licence question;
* 3.2 MB / 17.4k lines across English, Devanagari Hindi, Roman Hinglish,
  tech/code, URL syntax, and copy-from-context passages;
* it exists so the *pipeline* can be run end to end offline, not to make a
  fluent model. It contains no TinyStories, no Wikipedia, no Sangraha, no
  HingCorpus — those arrive in P4 with licence verification recorded in
  [DATA_LICENSES.md](DATA_LICENSES.md).

`data/raw/`, `data/processed/`, `training/checkpoints/` and
`training/datasets/` are git-ignored (§17 data hygiene).

## 2. Build the data (§7.3)

```bash
python -m training.scripts.make_seed_corpus          # → data/raw/seed/*.txt
python -m training.scripts.prepare_data \
    --tokenizer ai/tokenizer/artifacts/seed-1k       # → data/processed/seed/**
```

The pipeline is `clean → normalize → dedupe → language-ID → filter → tokenize
→ shard (binary memmap) → train/val split with leakage checks`, and it
reports what it dropped:

```
kept 17,265 / 17,402 lines (137 dropped)
  dropped by reason:
    near_duplicate         137
  languages: {'en': 8901, 'hi': 4191, 'hinglish': 4173}
  masked to placeholders: 6 public facts (withheld: 1)
leakage: clean (train 16,893 / val 372, exact 0, near 0)
  shard train   749,590 tokens in 68 file(s)
  shard val      16,801 tokens in 2 file(s)
```

Decisions worth knowing, because each one is a place a corpus project goes
quietly wrong:

* **PII becomes a placeholder, not a redaction.** A public fact's value
  (`https://…vercel.app/`) is replaced by its own token
  (`<|fact:project.volunteer.live|>`); the model therefore *cannot* learn
  to type the URL out (§7.2). The withheld phone number is not masked — the
  line is rejected, because a value that is in neither the placeholders nor
  the answers should not be in the weights either.
* **Unknown URLs lose their query strings or the line is dropped.**
  `github.com` survives (the tokenizer must see URL syntax); an arbitrary
  host with `?id=` does not.
* **Dedupe threshold is measured, not guessed** (4-word shingles,
  Jaccard ≥ 0.8): exact copy 1.00 dropped · sentence + appended clause 0.88
  dropped · one slot changed 0.68 *kept* · parallel construction
  ("his skills" / "his projects") 0.17 *kept*. The kept cases are the ones
  that teach the tokenizer anything.
* **Leakage is checked twice** — exact hashes *and* near-duplicate overlap
  between splits — and the run **exits non-zero** if either fires.
* **Toxicity filtering is a 6-word blocklist, and is labelled as such.** It
  is not a classifier and P4 replaces it, recording what it missed.

## 3. Train the tokenizer (§7.2)

```bash
python -m ai.tokenizer.train \
    --corpus "data/raw/seed/*.txt" --vocab-size 1024 \
    --out ai/tokenizer/artifacts/seed-1k

python -m ai.tokenizer.fertility ai/tokenizer/artifacts/seed-1k
```

The trainer **refuses** if the corpus cannot support the requested vocab:

```
trained vocab is 1935, requested 4096. The corpus is too small to justify
this vocabulary — either lower --vocab-size or add corpus (a mismatched
vocab silently resizes the embedding layer).
```

That refusal is not politeness. A smaller-than-requested vocab would leave
`ModelConfig.vocab_size` and the artifact disagreeing, and every parameter
count, export and parity check downstream would inherit the disagreement.

After training, three contracts are checked and printed: the six special
tokens exist, **all 63 placeholders are single tokens** (a multi-token
placeholder can be corrupted token by token), and seven probes round-trip
byte-exactly (English, Devanagari, Hinglish, SQL, URL/email, emoji, turn
tokens).

For the real run, the vocab decision is made from the fertility table on the
licensed corpus, within §7.2's 12–16k window (hard ceiling 32k in code).

## 4. The smoke train (§7.5)

```bash
# what a machine without torch can run (this one):
python -m training.scripts.train_smoke --pipeline-only

# the real thing: 1.82M params, ~50 CPU steps, checkpoint every 10
python -m training.scripts.train_smoke --steps 50 --save-every 10 \
    --tokenizer ai/tokenizer/artifacts/seed-1k \
    --shards data/processed/seed/shards \
    --run-dir training/checkpoints/smoke --gate

# then prove the resume
python -m training.scripts.train_smoke --steps 50 --resume auto --gate
```

It prints the analytic parameter count, builds the module and asserts the
count matches, trains, evaluates on a fixed validation sample, and ends
with:

```
loss: 6.93 → 5.41 over 50 steps (…s, …s/step)
gate 'loss decreases': PASS (window 5: 6.9 → 5.5)
```

`--max-minutes` stops cleanly and checkpoints, for Kaggle session limits.
`--gate` exits non-zero if the loss did not decrease — the smoke test is a
gate, not a demo.

## 5. Checkpoints and resume (§7.5)

| Requirement | Implementation | Verified how |
|---|---|---|
| `latest`, `best`, `step_N` | all written; `step_N` pruned to `keep_last` | `test_checkpoint.py` |
| model + optimizer + scheduler + GradScaler + step + epoch | one state dict, **required keys enforced on save and on load** | same (a state missing `scaler` is refused) |
| config + tokenizer version | in the state; compared to the live run before resuming | `train_smoke.py` |
| RNG states | python + numpy + torch (+CUDA) captured/restored | `test_checkpoint.Rng` |
| data-shard cursor | `TokenBatcher` state (RNG + tokens consumed) | `test_checkpoint.DataCursor` |
| atomic writes | temp file in the same directory → `os.replace` → fsync | `test_checkpoint` (no `.tmp` left behind) |
| auto-resume | `--resume auto` → `latest.pt`, with its age/size reported | `resolve_resume` tests |

The data cursor is the part that earns its keep. Resuming restores the RNG
*and* the token counter, so continuation is exact:
`test_resume_continues_the_exact_stream` asserts that a resumed batcher
produces the identical next six batches an uninterrupted run would have —
no repeated tokens, no skipped span.

`training/RUN_MANIFEST.json` is written per run: seed, config, tokenizer
version, hyperparameters, shard hashes and git commit.

## 6. Kaggle (P4) — the runbook

The notebook `training/notebooks/train_stage_a.ipynb` is a **driver**, not an
implementation: every step calls a module that is already in the repository and
tested, because §7.5 requires training to work without the notebook.

### 6.1 The licence gate comes first

Nothing can be downloaded until the terms have been read and recorded:

```bash
python -m training.scripts.fetch_corpus --check      # what is blocked, and why
python -m training.scripts.fetch_corpus --verify hindi_wikipedia \
    --spdx CC-BY-SA-4.0 --url https://dumps.wikimedia.org/legal.html \
    --reviewer "Aashish Kumar"
python -m training.scripts.fetch_corpus --source hindi_wikipedia
```

`data/sources.json` is the machine-readable record; `--verify` is the only
command that unblocks a source, it demands a concrete SPDX id (writing
`UNKNOWN` into a flag is refused), and **there is no `--force`**. An unverified
source is a decision nobody has made yet, and a fetch that stops for a decision
costs minutes. `docs/DATA_LICENSES.md` must be updated alongside it.

Downloads resume: a partial file is kept as `.part`, continued with a `Range`
request, hashed, and **deleted** if the hash does not match — so a corrupt
shard cannot later look like a real one, and a restarted session does not begin
a 2 GB dump again.

### 6.2 The order that catches problems cheapest

1. **smoke first** — `train_smoke.py --steps 50 --gate` (~2M params). It is the
   pipeline gate, not a quality result.
2. **`prepare_data`** on the fetched corpus; read the drop counts and the
   leakage verdict. A pipeline that silently loses half the corpus is a data
   problem that no learning rate fixes.
3. **train the tokenizer** at 12–16k, print the fertility table, then **freeze**
   the vocabulary. The trainer refuses a vocab the corpus cannot justify.
4. **`count_parameters.py --config A --gate`** — analytic and materialised.
5. **Measure throughput for ~100 steps**, then decide the budget:

   ```bash
   python -m training.scripts.estimate_budget --config A --from-run smoke.json \
       --hours 9 --dataset-tokens data/processed/stage_a/shards
   ```

   §7.3: the budget is decided *after* measuring tokens/sec, and "~20 tokens per
   parameter" is a reference. The tool answers the question a Kaggle session
   actually asks — **does the reference fit in the hours I have, and if not, how
   many hours does it need?** At 4,200 tokens/s (a plausible CPU-ish number) the
   reference budget for config A takes ~50 GPU hours, i.e. ~5–6 sessions against
   the free tier's ~30 h/week; on a T4 expect the *measured* figure to differ by
   a large factor, which is exactly why it is measured first.

6. **Stage A training, resumable:**

   ```bash
   python -m training.scripts.train_stage_a \
       --config A --tokenizer ai/tokenizer/artifacts/stage-a-12k \
       --shards data/processed/stage_a/shards \
       --run-dir /kaggle/working/checkpoints/stage-a \
       --steps 20000 --batch 16 --block 1024 --grad-accum 4 --amp --gate \
       --max-minutes 540 --resume auto
   ```

   `train_stage_a.py` is the smoke loop with Stage A's defaults (config A, lr
   3e-4, 200-step warmup, 65K tokens/step), **not a second implementation** — a
   second training loop is how "the resume is verified" stops being true of the
   thing that actually trained. Every later session runs the identical command:
   it resumes from `latest.pt` and reports the step and the tokens consumed.

### 6.3 Persistence, because sessions die

Checkpoints must be pushed outside the ephemeral session (§7.5): a Kaggle
Dataset, Drive, or the Hub — or `/kaggle/working` plus a Save Version each time.
`--max-minutes` stops cleanly and writes a checkpoint before the time box ends,
so an interrupted run is a resume rather than a loss.
